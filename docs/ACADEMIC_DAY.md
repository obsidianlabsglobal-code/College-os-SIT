# Timetable and attendance

An institutional admin selects a rostered instructor and an existing campus room, enters the first class in institutional local time, and saves a draft of one to sixteen weekly occurrences. Only admins see drafts. Publish checks the whole series in one transaction. PostgreSQL exclusion constraints protect sections, instructors and rooms. The booking service and class scheduler use the same per-resource lock, so a classroom cannot receive a confirmed event and a published class for overlapping times. Adjacent times can coexist. Past publication supports authorized backfill. Moving or cancelling an individual future occurrence requires the current revision and a reason.

Students see published classes for active enrollments, faculty see their own assigned classes, and HODs see published class records for their current departments. The next-class card reads the same scoped source. Timetable reads are limited to a day or seven days. Recurrence uses institutional wall time for each occurrence, and ambiguous or skipped DST times are rejected.

After a class ends, the assigned faculty member can mark the active student roster present or absent and submit the entire set at once. The first save records the class as conducted and creates a roster snapshot. Corrections retain the original snapshot and require a reason. Session revision checks reject stale submissions, and PostgreSQL stores every attendance revision and its marks alongside a metadata-only audit event. A published but unmarked class contributes nothing to attendance. The student sees only their own current marks for active offerings. Percentages are present marks divided by recorded marks with one decimal place. The what-if calculator uses the same numerator and denominator and makes no writes.

## Boundaries

This slice schedules whole sections. Lab subgroup allocation, institutional holidays and reusable break rules, instructor substitutions, and delegated coordinator grants need additional scope and policy. An authorized admin can cancel an individual occurrence with a holiday reason. Attendance uses the active roster at first recording, including when recording a backfilled session. It does not reconstruct historical enrollment or calculate official eligibility. Approved leave and student-initiated correction requests are later work. Corrections are performed by the assigned faculty member, with a reason and audit history. There is no operator interface for reviewing the full timetable revision history. Attendance summary aggregates current active offerings and has no institutional-scale benchmark.

The academic domain exposes scoped next-class, timetable and attendance summary reads in lib/academic-day.ts. These can be wrapped by an AURA gateway with the authenticated scope. Attendance writes remain human-reserved.

An active administrator can set or withdraw an advisory whole-percentage target per course offering and identify the policy source. Migration 012 retains every version. Concurrent edits must reload the current revision. The student forecast compares the unrounded fraction with the target and shows the reference. No default institutional threshold or exam decision is implied.
