# Event resource booking

Scope is one CLUBVERSE event reserving a room or a single equipment item. An institution administrator creates the catalog entry and grants a current member time-bound authority for one resource. An active club officer requests the resource from event detail. The current custodian confirms, declines with a reason, or cancels a pending or confirmed request. An officer can also cancel their club's request with a reason. A requester cannot confirm or decline their own request. Club and resource permissions remain independent.

Events already store validated timestamps. The request inherits the event interval and uses the institution timezone for display. Half-open intervals allow a booking to start as another ends. Availability returns resource metadata and a busy flag. The custodian queue shows interval and status without private event title, participant data or club content. An event cancellation releases active bookings and writes audit events in the same transaction.

PostgreSQL migration 010 uses tenant-qualified keys and a partial GiST exclusion constraint for confirmed overlaps. The service serializes confirmation per resource, locks the event and checks current membership and custodian expiry. Conflicts leave the request pending and explain the next action. Repeating a live request or a just-applied decision returns the existing booking. Revisions guard stale forms. The migration role needs permission to create the provider-supported btree_gist extension. The runtime role only gets required column grants.

Status and reasons are persistent in the organizer's Booking updates and the custodian queue. These views provide in-app status updates. Proactive push, email and delivery receipts are separate notification work. Equipment is reserved as one catalog item, with no quantity or custody model. The first catalog and grant lists show up to 100 entries and the member selector up to 200. Search and pagination are needed before piloting above those limits. The custodian queue is paginated. Capacity is recorded when verified, while event approval remains responsible for confirming suitability.

Track request-to-decision time and organizer follow-ups in an authorized pilot. The controlled concurrency test asserts that two overlapping requests cannot both be confirmed. Additional pilot policy decisions include who owns each room, operating hours, priority, cancellation and enforcement against existing room-allocation sources.
