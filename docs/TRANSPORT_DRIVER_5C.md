## Driver flow

The driver-only PWA at `/driver` has a distinct manifest, icons and service-worker scope. The HTML shell is generic. The service worker does not cache app data, responses with credentials, or cached signed-in pages. If reopened offline it displays an explicit offline page, not a fake live view. An open app keeps eligible offline actions in a bounded, session-scoped local queue, replays through the same server authorization and current trip/motion gates, and marks them sent only after a server receipt. A command UUID is scoped to the driver and payload. Optional report photos and free-text end notes are not stored in the offline queue. A queued SOS is not delivered: use the separate configured transport-office call option when appropriate. This is not an emergency-services integration.

The transport office enrolls a vehicle phone with a one-use, time-limited code and sets distinct 4-digit PINs for the authorized driver and optional backup. The PIN is bound to that enrolled phone, server-peppered and salted, lockout protected, and revocation invalidates the session. The cookie is path-scoped, HttpOnly, SameSite Strict and Secure unless an explicitly enabled loopback fixture is in use. Do not reuse telemetry or QR display credentials for a driver PIN session. Configure a separate server-only `NEXUS_DRIVER_PIN_SECRET` for pilot use and rotate/enroll via the office, never Git.

The ten areas in brief order cover today's duty, pre-trip checks, starting the real persisted trip, stops/approximate seats/door QR, parked quick reports, hold-to-send SOS, office messages/read-aloud/acknowledgement, end/odometer/issues, own records/documents, and leave or backup swaps. Use conservative motion authorization: with active telemetry missing, stale or not demonstrably parked, all interactive controls except SOS/callback and office speech are unavailable. Staff may close a trip from their own workspace if a driver loses the verified parked signal. The app does not generate GPS fixes. SOS repeats refresh the durable case even when duplicate delivery is suppressed. Students cannot read driver identity, contact or photos. Optional quick report photos are resized on-device, stored privately against the incident and served only to the owning institution's currently authorized transport office. Do not photograph students; no photos are sent to riders.

The existing one-shot transport scheduler also records driver duty reminders at 15 minutes and document reminders at 30/7 days when invoked. Those entries are idempotent and available to the driver in-app. Pilot infrastructure must register the scheduler and validate Android delivery while the PWA is closed; this source change is not evidence of background handset delivery. Verify Kannada and English speech on the actual low-cost Android model, install/Add to Home Screen, weak network, pickup timings, office phone routing and the actual office shift protocol before using the driver PWA on a real bus.

## Item 7 scanning

The rider continues to request camera access explicitly. Use platform QR detection when usable; otherwise load [jsQR 1.4.0](https://github.com/cozmo/jsQR) on the scanner path. Apache 2.0 notice is retained. npm tarball SHA-1: `8efb8d0a7cc6863cb6d95116b9069123ce9eb2d1`. The compiled upstream UMD distribution is unchanged except for an ESLint suppression on its first line and a CommonJS extension. With a known black-on-white QR, the fallback works on capped canvas frames without a CDN or upload. Only the recognized text enters the existing signed-code form; manual entry survives camera denial and decoding failure. Tracks stop when a code is found or the preview closes.

Run the existing Chromium suites, including the two mobile transport workflows and the opt-in driver test. For WebKit, use `playwright test --config tests/transport-webkit.config.ts` with a local seeded database and the existing transport fixture flags. That test uses a real generated boarding QR decoded in WebKit through a deterministic camera-frame substitute; it verifies storage, denial/manual UI and track release. This is not a physical iPhone camera test.
