# Innovation lab

Moodle documents text and file assignment submissions, grading, and feedback. Basic assignment handling establishes a capability baseline. The open question is whether connecting academic and institutional workflows reduces administrative work in a pilot. [Moodle assignment documentation](https://docs.moodle.org/500/en/Using_Assignment)

| Research direction | Proposed experiment | Failure condition |
| --- | --- | --- |
| Institutional Outcome Graph | Use curated relational links to test whether students can discover relevant mentors, projects and labs | Relevance and verified connections fail to improve over keyword search |
| Learning Recovery Engine | Use faculty-approved concept mappings and a pre/post practice assessment | Students show no measurable improvement in understanding |
| Opportunity Equity Engine | Compare eligible reach and applications against the institution's existing channels | Reach fails to improve or eligibility explanations prove unreliable |
| Campus Execution Engine and Friction Map | Compare enrollment-letter turnaround and rework with the existing process | Accuracy or accessibility deteriorates, or turnaround stays unchanged |
| Campus Decision Simulator | Compare schedule feasibility under documented resource assumptions | The simulator misses required constraints |
| AURA | Evaluate grounded retrieval first, then test confirmation and permissions for proposed actions | Citations or access bounds fail evaluation |

All experiments remain planned. Before asserting differentiation, research comparable products and peer-reviewed evidence for the specific capability under test.
