4. Collision rules

  1. Branches. Codex works on codex/<track>, cut from the latest audit/nexus-engineering-audit. It rebases before each push, never force-pushes a shared branch and never pushes to main. The founder merges track branches into the audit branch by pull request.
  2. Migrations. Claude uses 030–039; Codex uses 040–064 by track as above. A migration never depends on a number from the other range that has not landed yet. Applied migrations are never edited.
  3. Shared files. Edit only by appending one marked block per track:
    • app/chrome.tsx: one destination line, label and icon.
    • app/styles.css: prefer a CSS module.
    • docs/NEXUS_MASTER_FEATURE_REGISTRY.md: only your own rows.
    • docs/NEXUS_ENGINEERING_LEDGER.md: append only.
    • docs/NEXUS_IMPLEMENTATION_DEPENDENCIES.md: append a paragraph when authority changes.
    Server actions go in a new file per track, such as app/actions/sports.ts. Do not edit app/actions/planning.ts or app/actions/cases.ts.
  4. Case engine. Only Claude changes case_record kinds and lib/cases.ts. When Codex needs a new kind, such as transport incidents or lost and found, it adds a ledger line headed "Request to Claude: case kind <name>" with the readers and the coordinator. Claude adds the kind in its next migration. Codex can build the rest of the module meanwhile.
  5. Notifications. New notification kinds need a visibility rule in notifications() in lib/automation.ts. Request it the same way. Do not edit that function directly.
  6. Test data. Tests create their own fictional rows tagged with a random suffix and delete them in after. The other tenant reuses fixture IDs, so isolation checks compare content, not IDs.

5. Per-track definition of done (same bar as Claude)

  1. Each write goes through a domain service with Zod input and a transaction. It locks the membership row, re-checks the role and roster in SQL, checks the current state, writes, then records an audit event (metadata only). The migration grants each column the service updates.
  2. tests/<track>.test.ts starts with // covers: IDs. It proves the main path and every denial: wrong role, other section, other tenant, stale state and double decision.
  3. tests/<track>.e2e.ts covers the main path, with screenshots copied to docs/evidence/<track>-<date>/. Every new page has no horizontal overflow at 390 px.
  4. Run the full CI order on a fresh database: migrate twice, seed, lint, typecheck, build, all integration tests, all browser tests, then the tutor test. Record the observed counts in the ledger. Regenerate scripts/record-test-run.py and scripts/traceability.py output.
  5. Set registry rows to Tested only with linked tests. Anything less gets a scope note in brackets, which counts as partial.
