# Campus Transport data model proposal

Use additive migrations and tenant-qualified foreign keys. Model route, direction, and versioned ordered stops with coordinates and optional route geometry. A service schedule refers to a direction revision. A trip instance fixes the service date, direction revision, scheduled stop times, and source mode. Vehicle assignment joins one physical bus to a trip and records the assignment interval. Vehicle records distinguish seated and permitted total capacities. Operator and device bindings have finite active windows.

Store positions, occupancy observations, arrival/departure events and ETA predictions separately from the trip. Position fields include device, trip, source event key, source and receipt instants, accuracy, latitude and longitude, and optional speed and heading. Idempotency is unique per tenant, device and source event. Keep a transactionally advanced latest-valid pointer for reads. Index tenant/trip/source time for observations. Record counts, source, current capacity snapshot, observation time and any correction reference. An observed total passenger count alone cannot establish seated availability unless the operating rules justify it.

Trip lifecycle is scheduled → preparing → active → completed, with paused/resumed and cancelled transitions. Disruption and delay are timestamped events, projected into status rather than used to erase lifecycle state. Alerts carry severity, author, route/trip/stop scope, effective time, expiry and publication state. Student eligibility and preferred stop do not imply attendance, boarding or current occupancy. Store reminder preference separately. Track event and configuration changes in audit history.
